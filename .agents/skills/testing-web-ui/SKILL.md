# Testing the TieOut AP web UI

## Run it
- `cd web && npm install` (once), then `npm run dev` — Vite serves http://localhost:5173. No backend/auth/DB; the TS engine runs fully client-side.
- Routing is hash-based: no hash → marketing landing page; `#app` → upload screen; `#run=<base64url>` → results restored directly from the URL.

## Inputs: CSV + Excel/TSV/semicolon since e5373d0 (PDF/image extraction re-added in PR #8 — see its section below)
- Since commit e5373d0 both drop zones accept `.csv,.tsv,.txt,.xlsx,.xls,.xlsm,.xlsb,.ods` (UploadPanel.tsx); conversion happens fully client-side in `web/src/lib/tabular.ts` (`fileToCsvText`: SheetJS for Excel, delimiter sniffing for text). Format fixtures on disk: `fixtures/{meridian_stmt,acme_ledger}.{xlsx,tsv}` and `*_semicolon.csv` — all three pairs reconcile to the same golden values as the CSVs.
- Since PR #8 (branch devin/1788933637-pdf-extraction) there IS a server API again: `web/server/devApiPlugin.ts` serves `POST /api/extract` from the Vite dev server (same handler as the Vercel function `web/api/extract.ts`, logic in `web/server/extract.ts`). On older branches start plainly with `npm run dev`; on PR #8+ see the extraction section below.
- Read-failure UX: a file that makes `fileToCsvText` throw shows a red note inside the drop zone ("Could not read <name>: <reason>") and Reconcile stays disabled. To trigger it, use a corrupt ZIP-signature file (`PK\x03\x04` + junk bytes, saved as .xlsx) — random bytes from /dev/urandom do NOT throw: SheetJS's text/PRN fallback "parses" them, giving a green chip with garbage rows (as-at stays empty so Reconcile happens to remain disabled, but no error shows).

## PDF/image statement extraction (PR #8, commits 65c8dbf + 25232d3)
- Start the dev server with secrets bound via the exec tool's `env` param (never on disk): `ANTHROPIC_API_KEY` + `ANTHROPIC_WORKSPACE_ID` (live vision extraction) and `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` (login gate AND endpoint auth — the server reads the same vars to validate callers). `TIEOUT_MOCK_EXTRACTION` (JSON RawExtraction, `python3 fixtures/make_mock_extraction.py`) bypasses Anthropic for keyless testing.
- Since 25232d3, when Supabase env is present `/api/extract` requires `Authorization: Bearer <supabase access token>`; unauthenticated curl returns 401 `{"reason":"unauthorized","detail":"sign in to read PDF or image statements"}`. The auth check runs BEFORE payload validation, so the 400 non-base64 rejection is only observable with a valid token. The UI attaches the token automatically (web/src/lib/extract.ts).
- Happy path: signed in at `#app`, upload `fixtures/smoke_stmt.pdf` via the statement drop zone → "Reading the statement…" busy state (Reconcile disabled) → in ~5-8s a blue note "Read 3 lines from smoke_stmt.pdf; they add up to the statement's printed closing balance.", supplier autofills MERIDIAN IND SUPPLIES, as-at 2026-07-31. The smoke PDF (total 1,474.00) reconciles against acme_ledger.csv to a deterministic "Ties out exactly" run with 9 findings — NOT the golden values (those need meridian_stmt.csv).
- Refusal path: any non-statement image (e.g. a desktop screenshot PNG) → live model refuses in ~10s with an amber note ending "You can still upload the statement as CSV." Since 25232d3 selecting a new PDF/image clears the prior statement chip immediately, so after a failed replacement the slot is empty and Reconcile disabled (assert this — the pre-fix bug kept the stale statement). Cosmetic nit: the note reads "…lines missing or empty You can still…" (no punctuation between detail and suffix).
- Privacy proof on PR #8+: Fetch/XHR across a signed-in session = supabase `/auth/v1/*` + one `POST /api/extract` per PDF/image upload (payload = `{media_type, data:<base64>}`; PDF base64 starts `JVBERi0`). CSV/Excel uploads and Reconcile still make zero requests.
- pkill patterns containing "vite" can kill your own exec shell (exit -1) — use `pkill -f 'node.*vite'` and run the restart as separate calls.

## AI column mapping + AI findings summary (PR #10, merged, live on https://tieoutap.com)
- Two more authenticated endpoints exist: `POST /api/map` (401 unauth: "sign in to map columns with AI") and `POST /api/summarize` (401 unauth: "sign in to generate AI summaries"); GET returns 405. Handlers: `web/server/map.ts` / `web/server/summarize.ts`; client `web/src/lib/ai.ts` attaches the Supabase Bearer token automatically.
- Mapping trigger: upload a CSV whose headers are NOT recognised by the loaders (e.g. `Doc Ref,Doc Date,Betrag`) into either drop zone → an amber offer box appears ("<file> doesn't use the standard column names…") with buttons "Map columns with AI" and "Dismiss". Clicking Map shows "Mapping…", then (a few seconds) the offer disappears, the file chip appears (accepted), as-at/supplier auto-derive from the mapped CSV, and a blue note reads "AI mapped the columns in <name>: Doc Ref → ref, Doc Date → date, Betrag → amount. Review before you rely on the run."
- Privacy proof: the `/api/map` request body is exactly `{kind, headers, samples}` (≤3 sample rows, cells truncated to 80 chars) — no file text; `/api/summarize` body is supplier/as_at/totals/gap/ties_out/findings/bridge strings only. Check via Network → Payload → view source.
- Dismiss check: upload a second nonstandard CSV, click Dismiss → offer box disappears, NO /api/map request fires, and the previously accepted statement chip is untouched.
- AI summary: renders only for signed-in users on a successful (non-diagnostic) run — a blue "AI summary" card between the totals header and the tabs. "Generate AI summary" → disabled "Summarising…" (~15-25s live) → narrative block + "AI-REWORDED SUPPLIER EMAIL" pre with a Copy button (flips to "Copied" for 2s; verify clipboard via `DISPLAY=:0 xclip -selection clipboard -o` — the box's X display is :0, not :1). Button becomes "Regenerate". The deterministic Email draft tab is untouched. Signing out on the results page removes the AI card immediately.

## Production guest AI-mapping diagnosis (tieoutap.com, /api/map)
- Guest flow on production: landing "Open the app" (or "Reconcile your own statement") goes straight to the upload panel with the green "Trying without an account" banner — no extra CTA click needed. Uploading files does NOT consume the guest run (only Reconcile does), so mapping-offer tests are repeatable.
- To trigger the mapping offer, generate an xlsx whose FIRST row lacks `ref`+`date` columns (see `hasEngineColumns` in web/src/lib/tabular.ts). A temporary generator pattern lives in `fixtures/make_excel_fixtures.mjs` (require `xlsx` from web/node_modules).
- Diagnostic ladder verified 2026-09: signed-out click on "Map columns with AI" always fires `POST /api/map` (payload `{kind,headers,samples}` — first sheet row as headers, ≤3 sample rows, cells cut to 80 chars) and gets HTTP **401** → UI "Mapping failed: sign in to map columns with AI". A 9MB/5000-row/40-col file with a merged title row behaves identically (title row becomes the "headers"; payload stays tiny). Headers are NOT truncated, so a header row whose JSON exceeds Vercel's 4.5MB body limit gets a clean HTTP **413** → UI "Mapping failed: request failed (HTTP 413)".
- "Mapping failed: could not reach the server: Failed to fetch" therefore means the browser fetch itself rejected (extension/ad-blocker, proxy/VPN, offline/DNS, or cross-origin serving) — it is NOT produced by guest auth, payload size, or odd first rows on Vercel. If chasing that error, collect the reporter's browser/extension/network context.
- DevTools on this box reopens with the 375px device emulation from prior sessions — hit Ctrl+Shift+M to exit before measuring desktop behavior.

## Proving nothing leaves the browser (pre-PR #8 branches)
- `web/vite.config.ts` registers only `react()` and `tailwindcss()` — no API middleware. A quick pre-check before recording: `curl -s -o /dev/null -w "%{http_code}\n" -X POST localhost:5173/api/extract` should print `404` (on PR #8+ it prints 401/400 instead — the endpoint exists).
- In DevTools → Network, tick **Preserve log** and note that the log only captures requests made AFTER DevTools opened — reload once or you will screenshot an empty list and wrongly call it proof.
- Filtering the Network list on `extract` still matches ~4 entries. These are Vite source modules served from `/@fs/.../ts/src/extract/*.ts` (the engine's extract/anthropic modules are still in the TS package and get fetched in dev). Click one and read the Request URL to show it is a `GET` of a `.ts` source file, not a POST to `/api/extract`.
- Cleanest client-side proof: with Preserve log on across all uploads/reconciles, click the **Fetch/XHR** type filter — it should read `0 / N requests` (file uploads would appear there; everything else is GET module/asset traffic).

## Supabase login gate (PR #6, branch devin/1788916722-supabase-auth)
- Auth is build-time optional: `web/src/lib/supabase.ts` returns `null` unless `web/.env.local` has `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` (never print these). With them set, `#app` with no run shows AuthPanel ("Sign in to reconcile") when logged out; landing, "See a sample run", and `#run=` share links stay public (they set the run directly).
- Sign-up needs a real inbox: use mail.tm — create the account via `POST https://api.mail.tm/accounts` (note: mail.tm strips dots from the local part), then log into the web UI (Account menu → Log in) with address+password to read mail visually. Supabase's "Confirm your email address" email arrives within seconds.
- The confirmation link redirects to http://localhost:5173 (Site URL is configured; NOT the localhost:3000 default) and auto-signs the user in via hash tokens — you land on the upload screen already authenticated. To test manual password sign-in, sign out first.
- Session restore after F5 is purely from localStorage: expect 0 fetch/XHR on reload (no token call unless expired). Supabase traffic only appears on sign-in (`/auth/v1/token?grant_type=password`), failed sign-in (same, 400 "Invalid login credentials"), sign-up (`/auth/v1/signup`) and sign-out (`/auth/v1/logout?scope=local` → 204, scope local since commit 270053f).
- Privacy proof: with Fetch/XHR filter + Preserve log across a signed-in upload+reconcile, the only entries are *.supabase.co auth endpoints; the token POST payload is just `{email, password, gotrue_meta_security}` — no CSV content. Caveat: the Supabase project ref appears in DevTools screenshots (URL column) — unavoidable; the anon key does not.
- A deliberate wrong-password attempt leaves a red `400 (Bad Request)` entry in the Console — expected, not an app error.
- Throwaway account from the 2026-09 test run: devintieout1788916989@uberip.com / TieOutTest!2026 (works for both mail.tm and the Supabase app account; already email-confirmed).

## Narrow-viewport testing pitfalls
- Chrome on this box will not resize below ~500 CSS px window width (wmctrl resize requests below that are ignored). For ~375px checks use DevTools device emulation (F12 → Ctrl+Shift+M, type width).
- In emulation, if content overflows horizontally Chrome zooms out to fit: `window.innerWidth` reports the content width (e.g. 393 at a 375 setting) and `visualViewport.scale < 1`. Check `documentElement.scrollWidth - clientWidth` for the real overflow amount and scroll horizontally to confirm visually.
- The landing MiniBridge 375px overflow (~369px min-content from nowrap `truncate` dt rows) was fixed in commit b428989 by adding min-w-0. The same bug pattern recurred in the PR #7 ResultCard (commit 5b3ba22): nowrap `truncate` dt rows force the card's min-content up even with `min-w-0` on the dt, because in Chrome the flex container's intrinsic min-content contribution to the parent grid column still uses the full nowrap text width. Result: 10px overflow at 375px (scrollWidth 385). Verified fix: add `min-w-0` to the card's wrapper (`div.flex.justify-center.lg:justify-end`) — that alone restores scrollWidth 375. Re-measure at 375px on every landing-card change.
- Fast overflow diagnosis: measure `scrollWidth - clientWidth`, then bisect by toggling `style.display='none'` on suspects in the console (card → dl → row) until scrollWidth drops to the viewport width; that names the forcing element exactly.
- The results findings table sits in its own overflow-x wrapper (scrolls internally at 375px; page scrollWidth stays 375) — internal table scroll is allowed, only page-level overflow is a failure.
- Ctrl+Shift+M can be swallowed if DevTools does not have focus (it may open the Chrome profile menu instead). The reliable path is F12, then click the device-toolbar icon at the top-left of the DevTools pane.

## Console-log pitfalls

- Console log buffers persist across page loads within a browser session, so `[vite] Failed to reload ...` HMR errors from earlier dev-server restarts or from a colleague's edits can appear even though the current build is clean.
